# slack-agent-cli v0.3.1

Paginated reads now work without an explicit `--limit`: `messages thread`,
`messages history`, and `conversations list` default to 50. Explicit values
outside 1-100 still return `INVALID_LIMIT` and exit 2. Thread results retain
the parent and replies; follow `meta.next_cursor` for additional pages.

Every `ok:false` response exits nonzero. API, auth, and transport failures now
exit 1; usage/input errors exit 2. Local recovery statuses 3, 4, 7, 8, and 9
remain, especially ambiguous writes at exit 9. Exits 5 and 6 are retired from
process output. Inspect `error.code` and `hint` for recovery, honor read backoff,
and never retry a write automatically. JSON envelope version 1 and its schema
are unchanged, including existing error codes, messages, and hints.

Both v0.2.3 and v0.3.0 already exited 2 for `INVALID_LIMIT`. A successful `jq`
consumer can mask that failure in a shell pipeline. Use `set -o pipefail` and
check `.ok` before treating `.data` as a message list.

```sh
brew update
brew upgrade abigotado/tap/slack-agent-cli
```

Or install from source with Go 1.25.14 or newer:

```sh
go install github.com/abigotado/slack-agent-cli/cmd/slack-agent-cli@v0.3.1
```

The annotated release tag triggers the verified CI source release, producing a
checksummed source archive, `release-manifest.json`, and `SHA256SUMS`.
